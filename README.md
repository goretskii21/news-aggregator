# News Aggregator

Telegram-агрегатор для приватной супергруппы с девятью темами. Источники на английском и русском; новости российских компаний и внутреннего российского рынка исключаются. Старый Telegram-канал выведен из рабочего режима.

- [Источники по категориям и результаты проверок](docs/SOURCES.md)
- [Подробные правила отбора](docs/FILTERING.md)

## Как работает

Cloudflare cron каждые 10 минут → RSS/API/HTML → нормализация → фильтрация и дедупликация → SQLite Durable Object NewsDelivery → Telegram Bot API с соответствующим message_thread_id.

Production использует src/production-worker.js и NEWS_PIPELINE_MODE=topics. HTTP-запросы возвращают 404: публичного интерфейса управления нет. В группе девять тем: Critical / Security, AI, GitLab / GitHub, Docker / Kubernetes, Cloud, Microsoft, Linux / Networking, Apple, Games.

Сбор включает 74 RSS/Atom, CISA KEV и девять дополнительных источников через адаптеры. Новые адаптеры обновляются раз в час с приватным KV-кэшем; ошибки тоже получают паузу, Retry-After учитывается. GitHub API при 403/429 переключается на официальную HTML-страницу advisories. Полнота HTML ниже: только первая страница, без полного диапазона версий. Hetzner пока отвечает 429; его реальный сбор не подтверждён.

## Как фильтруются новости

Русский — язык чтения пользователя, а не привязка к российскому рынку. OpenNET, Comss и другие русскоязычные издания остаются источниками мировых технических новостей.

| Правило | Что происходит |
|---|---|
| Свежесть | Только записи с датой за последние 48 часов. Без даты и более чем на 15 минут из будущего — исключить. |
| Российский внутренний рынок | Заголовки с «В России», «Для россиян», «Российский…», «РФ», Russia/Russian — исключить. |
| Российские компании | Исключить заголовки про Яндекс/Yandex, Сбер/Sber, VK, Mail.ru, Касперского/Kaspersky и другие названия из списка в src/editorial-policy.js. |
| Язык и домен | Русский язык, российский домен издания или имя автора сами по себе не служат причиной отказа. Проверяется содержание заголовка. |
| Повторы | Удалить tracking-параметры ссылок, совпадения URL и нормализованных заголовков; очередь помнит отправленные URL. Общего смыслового сравнения между языками пока нет. |
| Шум | Убрать рекламу, купоны, розыгрыши, вебинары, слухи, beta/RC и другие нерелевантные материалы. |
| Категория | Ключевые слова и специализация источника; для широких лент проверяется заголовок. |
| Приоритет | Официальные источники выше редакционных. В Games дополнительный приоритет Diablo IV, AION 2 и основного WoW, но тема не ограничена этими играми. |
| Apple | Фокус на ОС, Mac/Apple Silicon и инструментах разработки; покупки аксессуаров и похожий шум исключаются. |

Примеры: «Яндекс представил новую AI-модель» и «В России запустили облако» исключаются. «Ubuntu 24.04: обновление ядра Linux» и «OpenAI представила новую модель» остаются кандидатами независимо от языка издания.

Правила по заголовкам не гарантируют распознавание любой российской компании и могут исключить заголовок с более широким контекстом, если в нём явно упоминается Россия. Список можно дополнять. Подтверждённая CISA KEV уязвимость используемого стека сохраняет приоритет безопасности, несмотря на географическое упоминание.

Правила версии 4 пересматривают обычные ещё не отправленные записи очереди. Critical и уже подготовленные задания отправки сохраняются. Подробности, полный перечень исключений и ограничения: [FILTERING.md](docs/FILTERING.md).

## Critical и обычные дайджесты

Critical требует одновременно релевантного продукта, признаков уязвимости и известной эксплуатации по CISA KEV. Стек: Docker Engine/Swarm разных поколений, Moby/containerd/runc, Ansible, Ubuntu/Linux kernel; пользователь использует Ubuntu 22.04+. Точных версий всех серверов пока нет, автоматического сравнения с инвентаризацией тоже нет.

Другие релевантные advisories учитываются в securityReview, но не становятся срочными автоматически. Это пока промежуточная оценка, а не полноценная ручная модерация; полного покрытия CVE не гарантируем.

- Все восемь обычных тем: **06:00 / 12:00 / 18:00 / 00:00 Europe/Kyiv**, с учётом летнего времени. Ночной выпуск без звукового уведомления.
- До **10 новостей на тему**, максимум **3 от одного источника**. Нет подходящих новостей — нет сообщения. До лимита не добавляется наполнитель.
- Critical — при очередном сборе, без ожидания дайджеста; это не поток реального времени.
- Длинный выпуск делится на сообщения с общей нумерацией, обычно на одну-две части.
- Отправляются исходный заголовок, источник и ссылка. Автоматического перевода и пересказа пока нет.

Новости разных тем отправляются последовательно, с общим ограничителем скорости группы. Пока в текущем окне есть готовые темы, очередь продолжает работу раз в минуту; десятиминутный cron не ограничивает скорость выпуска. При 429 Telegram учитывается retry_after. Подтверждённые части сохраняются отдельно; при восстановлении повторяется неотправленная часть. Если Telegram принял сообщение, но подтверждение потерялось, повтор всё же возможен.

Подготовка новых обычных выпусков допускается в первые 30 минут окна. Обычные записи истекают через 48 часов пребывания в очереди; Critical и подготовленные задания повтора автоматически не истекают. Предел очереди — 2000 записей; превышение вызывает ошибку. Отправленные URL сохраняются на 30 дней.

## Production и автодеплой

GitHub main → Cloudflare Workers Git integration → автоматические проверки → деплой. Cloudflare сам устанавливает зависимости через pnpm install --frozen-lockfile.

~~~text
Build command: pnpm run check && pnpm run smoke
Deploy command: pnpm exec wrangler deploy
Node.js: 22+
~~~

Повторный npm install не нужен: он конфликтует с установленным через pnpm node_modules (ошибка edgesOut). Wrangler закреплён в package.json. Ручной деплой обычно не требуется.

В wrangler.toml заданы NEWS_PIPELINE_MODE=topics, TELEGRAM_DELIVERY_ENABLED=true, TELEGRAM_GROUP_CHAT_ID и cron. Секрет токена новой группы — **TG_NEWS_BOT**. Маршруты тем — src/delivery-queue.js. Для паузы рассылки поставить TELEGRAM_DELIVERY_ENABLED=false и выполнить обычный Git-деплой.

Старый src/worker.js сохранён как legacy и содержит общие функции разбора RSS. Старые TELEGRAM_BOT_TOKEN / TELEGRAM_CHANNEL_ID больше не используются в режиме topics. Откат поведения на legacy требует сохранить экспорт NewsDelivery, binding и миграцию; нельзя вслепую откатываться к версии до создания класса.

## Хранение и диагностика

- Durable Object NewsDelivery — очередь, отправленные URL, задания и подтверждения частей.
- NEWS_CACHE / topics:diagnostics — закрытый снимок последнего cron: статусы источников, выбранный transport, счётчики отказов rejectedByReason, очередь по темам и примеры следующих сообщений.
- NEWS_CACHE / adapters:v2:* — ограниченный по времени кэш нормализованных данных адаптеров.
- Старые news:all и telegram:sent:* относятся к legacy; новая очередь ими не управляется.

Диагностика не доступна через публичный HTTP. Причины отказа считаются за текущий сбор и могут повторно учитывать одну отклонённую запись в следующих запусках. Секреты не пишутся в отчёты. Локальные .dev.vars, .wrangler/, node_modules/ и outputs/ исключены из Git.


## Локальная проверка на Windows

Docker для запуска Worker не требуется. Для текущей очереди используйте **wrangler.topics.local.toml**, отдельный порт 8788 и локальное SQLite-хранилище. Отправка по умолчанию выключена; облачная production-конфигурация не меняется.

~~~sh
pnpm run check
pnpm run smoke
pnpm run build:topics
pnpm run test:delivery-runtime
pnpm run dev:topics
~~~

Настоящие токены при необходимости хранятся только в игнорируемом .dev.vars:

~~~dotenv
TG_NEWS_BOT=<токен тестового бота>
TELEGRAM_GROUP_CHAT_ID=<ID тестовой группы>
~~~

Запуск в test-scheduled позволяет вызвать локальный cron вручную. Постоянный таймер для нового локального обработчика не запущен; сон Windows и остановка процесса останавливают локальную работу.

Старые wrangler.local.toml, scripts/local-tick.mjs и --watch относятся к legacy: они могут отправлять сообщения в General и не проверяют текущую маршрутизацию тем. Для новой очереди их не использовать.

Контролируемый live-тест новой очереди: test/telegram-topics-live.mjs. Он требует явного --send и использует защитный журнал от повторной отправки; не запускать в CI и не повторять без проверки журнала. Основные тесты используют фиктивный Telegram и не отправляют сообщения.
